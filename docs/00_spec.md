# Aiteru 仕様書（TimeRex 準拠）

面接・打ち合わせの日程調整 Web アプリ。仕様は TimeRex（timerex.net）の公式ヘルプセンターの記載に合わせる。
製品名・ロゴ・配色は TimeRex とは別のもの（Aiteru）を使う。

凡例: ✅ 実装済み / 🔜 未実装（設計のみ）

## 1. 登場人物

| 名前 | 説明 |
|---|---|
| 管理者 | 管理画面（`/admin`）で日程調整カレンダーを作り、予定を確認する人 |
| メンバー（面接官） | 面接を担当する人。管理画面で名前とメールアドレスを登録する |
| 応募者（ゲスト） | 日程調整ページ（`/c/<URL>`）で日時を選び、名前とメールアドレスを入れる人 |

**ログインはない（TimeRex との違い）。** 管理画面も応募画面も URL を開くだけで使う。
本番では管理画面のパスだけを Cloudflare Access で社内に限定する（docs/01「ログイン」）。

## 2. メンバー（面接官）と連携

- ✅ メンバーの登録・変更・削除（名前・メールアドレス）
- ✅ メンバーごとの Google カレンダー連携（OAuth。ログインではなくカレンダーの読み書きの許可だけ）
- ✅ 連携カレンダーの設定: 「空き確認に使うカレンダー」（複数）と「予定を登録するカレンダー」（1つ）
- 🔜 Outlook 予定表（Microsoft 365）連携

## 3. チーム（TimeRex のスペース・招待・権限）

- ログインがないため作らない。メンバーは全員1つの管理画面で扱う

## 4. 日程調整カレンダー（通常）

### 4.1 基本設定
| 項目 | 仕様 |
|---|---|
| 日程調整カレンダー名 | ゲストに表示される名前（必須） |
| 非公開カレンダー名 | ホストだけが見る管理用の名前（任意） |
| URL | `/c/<スラッグ>`。英数字とハイフン、3〜64文字。重複不可 |
| 所要時間 | 15〜480 分、1分単位 |
| 前後の確保時間 | 前・後それぞれ 0〜180 分。候補は「所要時間＋前後の確保時間」の空きがある枠だけ。確定時、ホストのカレンダーに「確保時間」の予定も登録（予定名は変更可） |
| 参加方式 | **全員が参加**（全員空いている枠のみ）／**誰か1人が参加**（1人でも空いていれば提示）／**2つのグループから1人ずつ**（各グループに空きがある枠） |
| 参加メンバー | 登録済みのメンバーから最大 12 人。2グループ方式では各人をグループ A/B に振り分け（重複不可） |
| 割り当て方法 | 誰か1人・2グループで、そのグループに2人以上いるとき。**均等（日程候補優先）**: 選ばれた枠に空きのある人のうち、このカレンダーでの担当件数が最少の人／**均等（担当件数優先）**: 担当件数が最少の人の枠だけを提示（誰か1人のみ）／**優先度順**: 空いている人のうち優先度が最も高い人 |
| Web会議 | 利用しない／Google Meet（✅ 自動発行）／Zoom・Microsoft Teams（🔜）。ほかに 電話・対面（住所）・自由記述 も選べる |
| ゲストに Web 会議 URL を非公開 | 発行はするがゲストの画面・メールに出さない |

### 4.2 詳細設定
| 項目 | 仕様 |
|---|---|
| 曜日ごとの受付時間 | 曜日ごとに受付する/しない と時間帯（1日5枠まで、`HH:MM`）。他の曜日へコピー可 |
| 特定の日の受付時間 | 日付ごとに上書き（受付しない も可）。曜日設定より優先 |
| タイムゾーン | カレンダーの基準タイムゾーン（既定 Asia/Tokyo）。ゲストは表示タイムゾーンを切り替えられる |
| 祝日の予約受付 | 受け付ける/受け付けない。日本の祝日（タイムゾーンが Asia/Tokyo のときのみ適用） |
| 提示期間 | **自動**: 何時間後から（0〜720 時間）・何日間分（1〜200 日、今日を1日目）／**日付を指定**: 開始日・終了日（終了日は開始日から 200 日以内）＋何時間前に締め切るか（0〜720）。終了日を過ぎると「受付期間外です」 |
| 日程候補の表示間隔 | 自動（所要時間と同じ）／15・30・60・120 分／カスタム 10〜120 分。各受付時間帯の開始時刻から間隔ずつ並べる |
| 予約受付件数の上限 | 日あたり（0:00〜23:59）／週あたり（月〜日）／月あたり。全員一律 or メンバー毎。予定の**開催日時**で数える。誰か1人方式ではメンバーごとに適用 |
| 主催者に知らせる | 都合の良い候補がないとき、ゲストが希望を書いてホストへ送れる |
| キャンセル・リスケ期限 | 未設定: 予定の終了時刻まで操作可／設定: 開始の N 時間前まで（0〜720） |
| 応募者への質問 | 既定: **名前（必須）・メールアドレス（必須）の2つだけ**。必要なら会社名・コメントなどを足せる。追加: テキスト・テキスト（複数行）・チェックボックス・ラジオ・セレクト・日付・数字。必須/任意、並べ替え。名前・メールは削除・任意化不可。🔜 ファイルアップロード |
| 表示名 | ゲスト画面に出すホスト名（例: 株式会社〇〇 採用担当）。空ならメンバー名 |
| 開始時・完了時メッセージ | 開始時はカレンダー上部、完了時は完了画面と完了メールに表示 |
| ゲストに完了メールを送る | オフにすると完了メール（Web会議URL・ICS）は送らない |
| リマインドメール | オン/オフ、送信時刻（前日 1:00〜当日 0:00 を 1 時間単位、既定 前日 16:00、ゲストのタイムゾーン基準）、冒頭メッセージ。送信先はゲストのみ |
| 日程調整受付状況 | 受付中／受付停止 |
| ホスト側メール | 完了・キャンセル・リスケの通知を受信する/しない |
| 通知先メールアドレス | 参加メンバー以外にも通知を送るアドレス（複数） |
| 予定のプライバシー | ホストのカレンダーに「非公開」で登録 |
| 予定名 | 連携カレンダーに登録する予定名。`{calendar}` `{guest}` `{company}` を差し込める |
| 閲覧パスワード | 設定するとパスワードを入れたゲストだけが候補を見られる |
| Webhook | 確定・キャンセル・リスケ時に JSON を POST |
| Slack 通知 | Incoming Webhook URL に通知 |
| 完了後の遷移先 URL | 指定すると完了画面の代わりにそこへ移動（広告のコンバージョン計測用） |

### 4.3 操作
- ✅ 作成・編集・複製・削除、URL コピー、受付停止
- ✅ **ワンタイム URL**: 1回だけ日程調整できる URL。完了すると無効。一覧・削除
- ✅ **パラメータ連携**: `?name=` `?email=` `?company=` `?q_<質問ID>=` で入力欄を事前入力。それ以外のクエリ（utm_* など）は予定に保存して CSV・Webhook に出す
- ✅ **ウィジェット**: iframe の埋め込みコード（`?embed=1` でヘッダーを消す）
- 🔜 グループ投票、セミナー（1枠に複数人）、ルーティング、会議室連携、確定後の参加者変更

## 5. 候補を選んで日程調整
- ✅ 予定名・所要時間（15〜480 分）・参加メンバー（最大 3 人、全員参加）・Web会議・プライバシーを入れ、メンバーの空き状況を見ながら候補枠を最大 20 枠クリックで選ぶ
- ✅ 発行される URL は1回限り。1人目が確定すると受付終了（完了済みの画面になる）
- ✅ 確定後のキャンセルはゲスト・ホストとも終了時刻まで可。日時変更は不可（作り直す）
- 🔜 候補枠を「仮予定」としてホストのカレンダーに入れる

## 6. 予定（確定した日程調整）
- ✅ 一覧（今後／過去／キャンセル、カレンダー・キーワードで絞り込み）、詳細（回答・Web会議URL・担当者）
- ✅ 管理者によるキャンセル（理由つき、応募者へメール）
- ✅ CSV エクスポート（UTF-8 BOM 付き、Excel で開ける）
- ✅ ゲスト: 予定確認ページ `/r/<トークン>` からキャンセル（理由）・リスケジュール（同じカレンダーの空きから選び直す）、ICS ダウンロード
- ✅ 連携カレンダーへの予定登録（Google Meet 自動発行、確保時間の予定）、キャンセル時の削除、リスケ時の付け替え

## 7. メール
| 種類 | 宛先 | 条件 |
|---|---|---|
| 日程調整完了 | ゲスト | 「ゲストに完了メールを送る」オン |
| 日程調整完了の通知 | 担当ホスト＋通知先 | 「ホスト側メール」オン |
| キャンセル | ゲスト・担当ホスト＋通知先 | 常に（ホスト側はホスト側メールの設定に従う） |
| リスケジュール | ゲスト・担当ホスト（新旧）＋通知先 | 同上 |
| リマインド | ゲスト | リマインドオン。前日 H 時（ゲストのタイムゾーン）。予定当日 0:01 以降に確定したものには送らない |
| 都合の良い日程がない | 参加メンバー＋通知先 | 「主催者に知らせる」オン |

送信手段は `EMAIL_PROVIDER`: `log`（送らずに DB の送信ログに残す。開発用）／`resend`（Resend API）。どちらでも送信ログ（email_outbox）に残す。
